# Auditoría de seguridad — Sitio Crubol (www)

Fecha: 2026-09-25 · Auditor: revisión adversarial (metodología `seguridad-saas`)
Commit auditado: rama `main` de github.com/fbolivar/www_crubol

## Resumen ejecutivo
El sitio es estático + cuatro endpoints públicos (asistente IA, contacto, diagnóstico
de dominio, informe PDF); no hay base de datos, autenticación ni pagos (ADR 0001), por
lo que RLS/Auth/Stripe no aplican. Se hallaron y **corrigieron** un SSRF en el análisis
TLS, la ausencia de headers de seguridad y la falta de rate limiting; quedan condiciones
de plataforma para el despliegue. Sin secretos en el repositorio y `npm audit` limpio.

## Veredicto: **APTO CON CONDICIONES**
No hay hallazgos Críticos ni Altos abiertos. El despliegue a producción queda
condicionado a los puntos C-01 a C-03 (configuración en Vercel).

## Verificaciones que PASARON
- **Secretos:** solo `.env.example` (valores vacíos) rastreado; `.env.local` ignorado; sin claves en el historial de git.
- **Dependencias:** `npm audit --omit=dev` → 0 vulnerabilidades.
- **Validación de entrada:** los 4 endpoints validan en servidor (tipos, formato de correo/dominio, tamaños); sin SQL (no hay BD).
- **XSS:** no se usa `dangerouslySetInnerHTML` salvo el JSON-LD estático; React escapa el contenido del asistente y del diagnóstico.
- **Correo:** el HTML de `/api/contacto` escapa entradas; anti-spam por campo trampa.
- **SSRF:** rechaza IPs literales y rangos privados/reservados/loopback/link-local (probado: `127.0.0.1`, `localhost` rechazados; metadatos 169.254.x cubiertos).
- **Headers:** CSP, HSTS, X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy presentes; sin `X-Powered-By`.
- **Rate limiting:** verificado (6.ª solicitud → 429).

## No aplica (ADR 0001)
- RLS / Supabase / multi-tenant: el sitio no tiene base de datos.
- Autenticación / middleware `/app/**`: no hay rutas protegidas (sitio de marketing).
- Pagos / webhooks Stripe: no hay pagos.

## Condiciones para el despliegue (C-01 a C-03)
- **C-01** Cargar variables de entorno en Vercel (Production + Preview), nunca en el repo:
  `ANTHROPIC_API_KEY`, `SMTP_HOST/PORT/USER/PASSWORD/FROM/TO`.
- **C-02** Confirmar que el repositorio **público** es intencional (no hay secretos, pero expone el código).
- **C-03** Habilitar rate limiting / WAF a nivel de Vercel para `/api/*` (el limitador en memoria es por instancia y no cubre serverless distribuido). Recomendado antes de exposición pública amplia.

## Recomendaciones futuras (no bloqueantes)
- CSP basada en nonce (elimina `'unsafe-inline'`).
- Mitigación de DNS rebinding (fijar IP resuelta o egress controlado).
- Verificación del correo del visitante en `/api/informe` antes de enviarle el PDF.
